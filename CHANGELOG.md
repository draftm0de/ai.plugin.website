# Changelog

## [Unreleased]

No release version and no publication date have been chosen. The state below is a local migration awaiting independent review; host acceptance is open (NOT RUN). Nothing here claims production readiness or full host support.

### Added

- Plugin **Website** (`website`) with five skills migrated from the former `zyris-website` plugin: `setup` (create, adopt, plan, verify), `preview` (local dev-server control and separate page inspection), `optimize` (SEO/accessibility audit, reports, work list, decisions, apply), `edit` (start page `src/pages/index.astro` only) and `publish` (placeholder; publishing is not available).
- Shared runtime and manifest schema under `skills/_shared/` (`website.schema.json`).
- German and English documentation (README, `docs/de`, `docs/en`), the acceptance matrix `docs/migration/acceptance.md` and the file-by-file completeness mapping `docs/migration/completeness.json`.
- Deterministic tests (unit, integration, contracts) on fictional fixtures with a fake npm; separately released real-npm tests under `tests/external/` (not run).

### Changed

- Manifest schema file renamed to `website.schema.json` (plugin `skills/_shared/resources/`, project `.project/specs/`, reference `./website.schema.json`). A project whose manifest references the former `zyris-website.schema.json`, or that has only that file and no `website.schema.json`, is refused with a diagnosis; an unused old file next to a correctly used `website.schema.json` is not by itself a reason. There is no fallback and no automatic migration.
- Plugin description in `plugin.json` now states the actual scope (the earlier skeleton wording is removed); the host manifest is derived from it.
- Project data formats (manifest `website.json`, ownership record `website.manage.json`, optimize markers) are unchanged.

### Fixed (protection corrections to inherited defects)

Small, separately rejectable corrections with regression tests; details and test references in `docs/migration/changes.md`:

- `preview`: launch file and state area are no longer followed through symlinks (BD-5, BD-6).
- `optimize`: CRLF files, non-UTF-8 files, leftover temp files, unreadable work lists, filesystem errors, overlapping/multiple replacements, symlinked sources and byte-exact work-list handling (BD-7 to BD-11, BD-15 to BD-17).
- `edit`: bytecode and resolver failures, a poisoned session after a refused site, symlinked `package.json`, unsafe backup areas, tracebacks for missing tools and write errors, whole-tree verification before removing a backup, session-file symlink handling, byte-exact `replace`/diff and pattern-based secret redaction before truncation (BD-18 to BD-25, BD-31, BD-32).

### Known limitations

- After `edit` changes a file generated by `setup`, the stored ownership hash no longer matches: `setup create` reports `conflict`, `setup verify` keeps the file (`modified (kept)`); no re-baselining.
- Protection limits that remain: a short race window between the hash check and replacement in `edit`; `O_NOFOLLOW` covers the last path component only; ancestors of the preview state base directory are not checked; secret redaction is pattern-based, not complete.
- Not available: publishing, blog and further pages, forms, `setup update`, GEO, Lighthouse, link-graph checks.

### Not verified

Real npm/Node runs, native Claude and Codex runs for every skill, model behaviour, any actual visual check, and a host import of the marketplace entry.
